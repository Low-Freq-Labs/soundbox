## Confirmation and source contract

Current source prepares bound history and storage metadata when the library materializes
and its source is verified. Opening Graveyard reveals that snapshot or its truthful
loading state; preparation never reads or hydrates audio.

- Graveyard selections bind logical/native IDs, native UUIDs, exact canonical
  paths, native memberships and current source/library/schema/version. Imported
  bindings must retain their UUID; duplicate/conflicting bindings stop the entry.
  Numeric labels, titles, equal audio bytes and stale caches cannot supply a path.
- The review lists each title/path and affected native playlists, the exact file
  count/size going to Trash, files already missing, shared files being kept, and
  unresolved entries that will remain in Graveyard. Cancel is the default. The
  entire plan/selection hashes persist before worker admission.
- Unselected active native entries keep their shared file; deletion never broadens
  to them. The real VOLATIVE example is removed93738342 and retained259251743:
  both point to the same MP3. Removing that duplicate Graveyard entry must keep
  the remaining Collection entry and that file. Separate paths are independent.
- Selected source mutations settle safely; selected detection retires only after
  confirmation. Unrelated detection/conversion/import jobs do not veto capture of
  a new Delete selection. Critical publication still serializes on the shared lane. Every actual source mutation uses the common
  desktop owner/lock/journal, accepted separate removal authority and fresh closed
  rekordbox/agent guards. Native metadata reads use stable private DB/WAL copies.
- Supported local sync0/1 removal follows the captured native protocol: physical
  removal of unsynced rows, retained synced tombstones, exact dependent cue/file/
  membership/tag/history/mixer handling, local counters, later membership position
  shifts and byte-preserving playlist XML timestamp changes. Unsupported/cloud or
  unknown linked metadata fails closed. No table purge or general orphan cleanup.
- Reviewed originals move into macOS Trash with a deterministic UUID suffix and
  exact original-path recovery receipt. Permanent unlink and emptying Trash are outside this feature. Paths
  outside the supported desktop volume, redirects, hardlinks and unowned files
  fail before disposal. SoundBox curation/analysis/import history remains.

## Recovery

Encrypted before/after DB/XML and exact owned native-resource backups precede
mutation. An interruption tag and durable returned Trash locations bind moved
files without scanning unrelated Trash audio. SQLite’s owned hot-journal recovery
precedes source-state classification; uncommitted files/resources/XML restore
without overwriting a changed occupant. Committed native/file disposal is verified
independently. Unknown states keep evidence and block other source domains.
GUI receipt-save failure retains the confirmed intent for idempotent retry.
Normal shutdown joins the source worker; accepted intentions survive restart.

Ordinary completed operations keep the latest full encrypted DB pair and permanent
row/XML/resource/operation receipts. Older exact DB payloads retire with their own
verified, resumable marker. Unresolved operations and native acceptance references
are never treated as disposable completed payloads. Cancel removes only exact
unstarted generated review copies.
